# FastAPI + витрина + ИИ

В `codex/ai-consultant` объединена история `origin/dev2` до `ee916bc`: подбор аналогов по правилам совместимости и подтверждение конкретного предложения. Сохранены витрина `web` и отдельный CLI из `src/`. Прежний `widget` остаётся в репозитории; Compose запускает `web`.

Стек: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy async, PostgreSQL 16, Alembic (восемь миграций). Точка входа `app.main:app`; маршруты → services → repositories/integrations. Запуск: [web/README.md](../web/README.md).

`OPENAI_API_KEY` включает асинхронный `ResponsesConsultant`: общие схемы Query/Draft и инструкции CLI, модель из `OPENAI_MODEL` (по умолчанию `gpt-6-luna`), Responses API, `store=False`, без инструментов записи. Сервер передаёт ограниченную историю текущей сессии и свежие факты каталога. ID товаров/источников и ссылки ответа проверяются. Без ключа сохраняется детерминированный маршрутизатор; опциональный прежний `LLM_API_*` provider также поддержан. Ошибка модели не превращается в выдуманные цену и наличие. Свободный текст модели всё равно требует оценки качества.

Вложения обрабатываются на сервере без передачи содержимого внешней модели. Извлечённые строки ищутся через тот же `CatalogService`; ответ сообщает о неизвестных позициях и неоднозначных количествах. Сообщения, связанные с вложениями, исключаются из истории для модели.

Настроенные EKT credentials включают mapper, проверенный по реальным ответам. Поиск идёт по частичному PostgreSQL-индексу; `/fresh` получает detail непосредственно по известному partner ID и проверяет соответствие артикула. Runtime использует только строки происхождения `ekt/live`; прежние demo-записи не участвуют в поиске. Подробнее: [EKT](ekt-integration.md), [каталог](catalog.md).

`OfferService` создаёт предложение, повторно проверяет цену/количество/остаток после явного подтверждения, сохраняет идемпотентный результат. Он использует отдельные DB-сессии для транзакций предложения и чтения каталога, чтобы autobegin при поиске не конфликтовал с confirm. `UnavailableCartGateway` не изменяет внешнюю корзину; runtime mock gateway удалён в новой dev2. Реального cart endpoint EKT нет в полученном контракте.

Настройки — в игнорируемом `.env`; `.env.example` содержит только placeholders. В Docker DB доступна по `db:5432`, с хоста — по `127.0.0.1:55432`. Порты Compose привязаны к localhost. Для Python-запуска на хосте добавьте `PYTHONPATH=src`, установите `requirements.txt` и системный Tesseract.

Перед публичным размещением нужны аутентифицированная привязка сессии и защита административных endpoints каталога. UUID сессии пока используется как идентификатор доступа. Это локальный прототип, а не внедрение на действующий ekt.kz.

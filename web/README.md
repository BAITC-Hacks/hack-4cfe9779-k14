# Демовитрина EKT и чат ассистента

Главная и страница каталога воспроизводят структуру публичного [nursultan.ekt.kz](https://nursultan.ekt.kz/) с изображениями из предоставленной папки `new reference`: шапка, баннеры, категории, новинки, предложения, блок о компании и футер. Экран демонстрационных товаров и корзина оформлены в том же стиле. ИИ-чат открывается поверх каждой страницы. Это самостоятельный прототип для хакатона: товары, цены и остатки в нём условные; сайт партнёра и его корзина не меняются.

Переходы внутри прототипа: главная `/`, каталог `/#catalog`, демонстрационные товары `/#products`, корзина `/#cart`. Материалы нового референса размещены в `public/reference/`; предыдущая папка `reference` для этого обновления не использовалась.

## Запуск

Нужен Node.js `^20.19.0` или `>=22.12.0`.

```bash
cd web
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. Без настроек включён демо-режим: чат показывает поиск, аналоги, проверку количества и добавление в локальную корзину только после кнопки «Да, добавить». Корзина хранится в `localStorage` этого браузера.

Для сборки: `npm run build`.

## Подключение Python-бэкенда

Создайте `web/.env.local` по образцу `.env.example` и задайте `VITE_ASSISTANT_API_BASE`. После этого чат отправляет запросы на сервер с `credentials: include`. При разных адресах frontend и backend сервер должен разрешить CORS для точного адреса витрины и cookies. Секреты каталога и ключи моделей храните только на сервере; переменные `VITE_*` попадают в браузерный код.

Контракт, который ожидает интерфейс:

1. `POST /assistant/messages` — JSON `{ "message": "...", "attachment_ids": [] }`. Ответ: `{ "reply": "...", "products": [], "proposal": null, "cart_url": null }`.
2. `POST /assistant/attachments` — `multipart/form-data` с полем `file`. Ответ: `{ "id": "идентификатор-вложения" }`.
3. `POST /assistant/proposals/{id}/confirm` — подтверждение показанного предложения. Ответ: `{ "reply": "Добавлено в корзину", "cart_count": 1, "cart_url": "https://..." }`.

Элемент `products` должен содержать `id`, `sku`, `name`, `category`, `price`, `stock`, `unit`, `specs` (массив строк) и `art` (`cable`, `breaker`, `lamp` или `tray`). Предложение: `{ "id": "...", "product_id": "...", "name": "...", "unit": "шт.", "quantity": 1, "available": 3 }`. Пока сервер не вернул `proposal`, интерфейс не показывает подтверждение. Количество в серверном предложении нельзя менять на клиенте: для другого количества нужно запросить новое предложение.

Сервер должен привязать предложение к сессии и конкретным товару/количеству, повторно проверить остаток перед изменением корзины и отклонить повторное или просроченное подтверждение. В ответах о товарах он должен использовать данные каталога, а не демонстрационные значения витрины. Для реального подключения к ekt.kz понадобятся доступы к корзине и способ встраивания UI от партнёра.

При настроенном API карточки демонстрационной витрины передают ассистенту артикул, но каталог витрины остаётся примером. Для выпуска на реальном сайте его нужно загрузить из согласованного API каталога.

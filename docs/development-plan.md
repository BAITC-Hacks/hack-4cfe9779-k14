# План разработки и технологический стек

Этот план развивает [архитектуру ассистента](architecture.md) для кейса HackAlem AI. Этапы идут в порядке зависимостей. MVP завершён, когда выполнены все пять обязательных критериев кейса, включая реальное добавление в корзину после подтверждения. Если партнёр ещё не предоставил механизм корзины, можно показать прототип на тестовой корзине, но это не заменяет интеграцию с ekt.kz.

## Рекомендуемый стек для MVP

| Слой | Технология | Почему здесь |
| --- | --- | --- |
| Чат на сайте | React + TypeScript + Vite, адаптивный CSS | Отдельный виджет с состояниями диалога, карточками товаров, загрузкой файлов и подтверждением. Сборка Vite позволяет встраивать виджет в существующий сайт. Способ встраивания согласуется с платформой ekt.kz. |
| Сервер и API чата | Python + FastAPI + Pydantic | API сообщений, вложений и подтверждения; проверка входных данных; удобная интеграция с Python-инструментами обработки файлов и моделью. |
| Вызовы API ekt.kz | HTTP-клиент `httpx` в отдельном адаптере | Basic Auth и детали товаров остаются на сервере; адаптер изолирует формат ответов и ошибки внешнего API. |
| Каталог и поиск | PostgreSQL: обычные поля + `jsonb` для разнородных характеристик, полнотекстовый индекс; точный поиск артикула отдельно | Достаточно для первого каталога без дополнительного поискового сервиса. Цена и остаток перед ответом проверяются в первичном API. |
| Сессии и предложения | PostgreSQL | Хранение контекста сессии, конкретного предложения к подтверждению и ключа идемпотентности. Истёкшие записи удаляются по расписанию. |
| Языковая модель | Один настраиваемый API-провайдер через интерфейс `LLMClient` | Модель разбирает запрос и составляет ответ по полученным данным. Выбор поставщика и модели зависит от допустимой передачи данных, задержки и бюджета. Запись в корзину контролирует серверная логика. |
| Вложения | `pypdf` для текстовых PDF, `python-docx` для DOCX, `openpyxl` для XLSX, Tesseract OCR для JPEG/сканов | Покрывает основные форматы из кейса. Поддержку старых `.doc`/`.xls` и качество распознавания нужно уточнить на реальных файлах. |
| Локальный запуск | Docker Compose | Поднимает виджет, API и PostgreSQL одной командой; секреты передаются через локальное окружение, без записи в Git. |

Решения для следующего масштаба: Redis для большого числа коротких сессий/кэша, отдельная очередь для массовой обработки файлов, поисковый движок или векторный индекс при слабом качестве поиска в PostgreSQL. Эти компоненты добавляются по измеренной потребности.

Выбор опирается на официальную документацию [React](https://react.dev/learn), [TypeScript](https://www.typescriptlang.org/docs/handbook/), [Vite](https://vite.dev/guide/), [FastAPI](https://fastapi.tiangolo.com/), [PostgreSQL](https://www.postgresql.org/docs/current/textsearch.html) и [Docker Compose](https://docs.docker.com/compose/). Документация библиотек вложений: [pypdf](https://pypdf.readthedocs.io/), [python-docx](https://python-docx.readthedocs.io/), [openpyxl](https://openpyxl.readthedocs.io/) и [Tesseract](https://tesseract-ocr.github.io/).

## Этапы разработки

| Этап | Что разработать | Готовый результат |
| --- | --- | --- |
| **0. Проверка интеграций** | Получить образцы ответа каталога, список полей и лимиты API; выяснить механизм корзины, сессии сайта и источник условий покупки; согласовать признаки аналогов и допустимые файлы. | Таблица соответствия реальных полей внутренней модели и список подтверждённых интеграционных контрактов. При неполных данных подготовлена репрезентативная синтетическая выборка для демонстрации. |
| **1. Каркас проекта** | Создать `widget/`, `api/`, конфигурацию, Docker Compose и шаблон переменных окружения без секретов; определить схему API чата и формат ошибок. | Виджет и сервер запускаются локально, сообщение проходит от браузера до сервера и обратно. |
| **2. Каталог и поиск** | Реализовать серверный Basic Auth адаптер, пагинацию, нормализацию и обновление индекса; точный поиск по артикулу и поиск по названию/характеристикам; получение свежих деталей товара. | Запрос по существующему артикулу возвращает корректные характеристики, наличие и сертификат, если он есть в данных. Неизвестные поля не выдумываются. |
| **3. Диалог и условия покупки** | Сделать историю в рамках сессии, определение намерения, уточняющие вопросы, вызовы поиска и ответы по утверждённым данным. Добавить источник оплаты, доставки и минимальной партии. | Посетитель может задавать свободные вопросы, продолжать диалог и получать содержательный ответ об условиях покупки. |
| **4. Аналоги** | Задать обязательные фильтры совместимости по категории и характеристикам; ранжировать оставшихся кандидатов; объяснять совпадения и различия. | Для позиции с нулевым остатком находится хотя бы один уместный аналог, если он есть в каталоге, с кратким объяснением. |
| **5. Корзина и подтверждение** | Состояние ожидающего предложения, точный состав и количество, подтверждение в той же сессии, повторная проверка остатков, идемпотентная запись, чтение результата и ссылка на корзину. | Без подтверждения корзина не меняется; после него количество не превышает остаток, ссылка открывает актуальную корзину. |
| **6. Вложения и мобильный интерфейс** | Загрузка и проверка файлов, извлечение текста/таблиц/маркировки, уточнение при неуверенном распознавании; адаптация чата для телефона. | Посетитель может отправить заявленные файлы и фото; найденные позиции проходят тот же сценарий проверки и подтверждения. |
| **7. Приёмка и демонстрация** | Пройти пять проверок из кейса, проверить скорость ответа в единицы секунд, ограничения по данным и обработку ошибок внешнего API; оформить инструкцию запуска и описание используемых данных. | Рабочий прототип, репозиторий и README с архитектурой, запуском и источниками данных. |

Этапы 1–4 и 6 можно развивать на репрезентативной выборке каталога, если рабочий API ещё не готов. Для этапа 5 нужен подтверждённый способ изменения корзины ekt.kz. Прямой доступ языковой модели к операции записи не предусматривается.

## Минимальные договорённости с партнёром

1. Доступ к тестовому API и примеры товаров: доступный, отсутствующий, с сертификатом, с несколькими складами.
2. Описание корзины: как определить её владельца, добавить позицию, прочитать итоговое состояние и построить ссылку.
3. Утверждённые тексты условий покупки и критерии взаимозаменяемости товаров.
4. Способ встраивания чата, требования к доменам и сессии; правила хранения вложений и диалогов.

Учётные данные из приложенного PDF не копируются в исходный код. Перед рабочим подключением партнёру следует выдать отдельные секреты для тестовой и рабочей среды.

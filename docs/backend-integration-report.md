# Отчёт: UI + FastAPI + ИИ + EKT

Дата проверки: 23 сентября 2026 года. Ветка: `codex/ai-consultant`. Объединён `origin/dev2` до `ee916bc` (аналоги, усиленный поток подтверждения корзины, удаление runtime-mock и обновление README). Ветки `develop2` на origin нет. Предыдущие изменения витрины сохранены коммитом `817d232`; текущая интеграция включает merge истории Git.

## Работает и проверено

- Полный `docker compose up -d --build`: PostgreSQL 16, восемь миграций, FastAPI, Nginx/web. Витрина на `http://127.0.0.1:8080`, Swagger на `http://127.0.0.1:8000/docs`. `/health` отвечает 200.
- Реальный read-only API EKT через серверный Basic Auth. Mapper написан по полученным list/detail JSON; credentials остаются в игнорируемом `.env`. Карточки используют настоящие изображения и ссылки. Страницы каталога, поиск и чат обращаются к одному `CatalogService`.
- Поиск артикула `200300285_`, свежая карточка ID `515291`: при проверке цена 64 920 ₸, суммарный остаток 23, Алматы — 5. Это наблюдение на момент запроса, не резерв. Чат с реальной `gpt-6-luna` ответил на вопрос о цене и наличии в Алматы. Повторная проверка после merge `ee916bc`: HTTP 200, 4,4 секунды на этот запрос.
- Общие Query/Draft и инструкции ИИ-модуля подключены к FastAPI через асинхронный Responses API. Сервер проверяет ID источников/товаров и ссылки. В модели нет инструмента записи в корзину; секреты ей не передаются. Статус API показывает источник `ekt` и наличие конфигурации модели, без ключа.
- Через web загружены сразу PDF, DOCX, XLSX и PNG. Повторная проверка после перехода на локальное извлечение: все uploads — 201, сообщение — 200. PDF/DOCX/XLSX распознали `200300285_`, количество 2, нашли реальный товар. OCR PNG запустился, но распознал `200300285` без `_`, а количество на другой строке не связал с артикулом; сервер вернул `unknown_article`/`quantity_ambiguous`, не подставил товар догадкой.
- Предложение создаётся из кнопки карточки и текстового запроса «Добавь 2 штуки 200300285_». UI показывает одно предложение сервера и отдельную кнопку подтверждения. Запрос confirm повторно проверяет товар и возвращает `cart_unavailable`, `cart=null`; пользователь видит, что товар не добавлен. Исправлен конфликт SQLAlchemy autobegin между чтением каталога и транзакцией предложения.
- На мобильной ширине 390 px и desktop 1440 px документ не имеет горизонтального переполнения. История хранится на сервере; session ID — в sessionStorage вкладки.

## Ограничения

| Возможность | Текущее состояние |
| --- | --- |
| Настоящая корзина/checkout EKT | Нет подтверждённого API корзины и привязки посетителя. Basic Auth каталога не предоставляет эти операции. Доступен только `UnavailableCartGateway`, без runtime mock. |
| Полный ассортимент в поиске | По умолчанию загружаются пять страниц, 100 товаров. Просмотр новых страниц расширяет индекс. SKU вне загруженной части не находится; подтверждённого endpoint поиска EKT нет. Поиск по характеристикам требует загруженных details. |
| OCR и произвольные спецификации | OCR может терять символы. Надёжнее таблица «Артикул / Количество»; неструктурированный текст и разнесённые строки могут требовать уточнения. До пяти файлов по 10 МБ; DOC/XLS не поддерживаются. |
| Передача файлов модели | Отключена: извлечение и сопоставление выполняются локально. Вложения и связанные сообщения не входят в контекст внешней модели. |
| Совместимые аналоги | Алгоритм из dev2 объединён и протестирован; правила совместимости отключены до утверждения партнёром. Для реальных EKT-категорий нужны согласованные параметры и правила. Похожее название не считается доказательством совместимости. |
| Сертификаты, доставка, оплата | Сертификаты не получены в проверенном API. Provider условий покупки возвращает unavailable. Эти сведения не выдумываются. |
| Дробные количества | Текущий контракт количества целочисленный; дробный остаток источника отмечается как неизвестный. |
| Публичное размещение | Проверен локальный Compose на localhost. Это отдельная витрина, а не установленный чат действующего ekt.kz. Для публикации нужны аутентификация посетителя и защита административных API. |

## Автоматические проверки

- `.venv/bin/python -m pytest -q`: 119 passed (после удаления mock-runtime и соответствующих тестов в новой dev2). Одно предупреждение Starlette о будущем переходе TestClient с httpx на httpx2.
- `npm test --prefix web`: 2 passed — проверка unknown/cache, контракта чата/файлов, отображения server pending_offer без повторного создания и отдельного идемпотентного confirm.
- `npm run build --prefix web`: TypeScript + production Vite.
- Реальный браузер и Compose: каталог/поиск, ответ модели по свежим данным, загрузка четырёх форматов, предложение и отказ неподключённой корзины, мобильная ширина.

Свободный текст модели проверен на конкретном живом сценарии; это не исчерпывающая оценка точности всех ответов. ID/URL-валидация не доказывает правильность каждой фразы. Противоречия источника (например, ток 160 А в названии и 250 А в properties выбранного товара) сохраняются и требуют уточнения у EKT.

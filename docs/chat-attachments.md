# Вложения в чате

## API

1. Создайте сессию: `POST /api/chat/sessions`.
2. Загрузите файл в неё: `POST /api/chat/sessions/{session_id}/attachments` с multipart-полем `file`.
3. Передайте возвращённый `id` в `attachment_ids` сообщения:

```json
{
  "content": "Подбери товары из этого файла",
  "attachment_ids": ["b8cc4e95-37bb-4b12-978c-eeb3a8132057"]
}
```

Файл обрабатывается `AttachmentService` до записи ссылки. В PostgreSQL сохраняются только нормализованные результат извлечения, таблицы, warnings и metadata; бинарные байты не сохраняются и не передаются в LLM.

## Обработка позиций

`AttachmentItemParser` сначала читает таблицы DOCX/XLSX с колонками `article`/`артикул`, `name`/`название` и `quantity`/`количество`, затем ищет в тексте помеченные артикулы и количества. Для каждого результата сервер:

1. ищет артикул или название в локальном `CatalogService`;
2. сообщает о неизвестной позиции или нескольких совпадениях;
3. для единственного совпадения получает актуальные цену, остаток и доступность через `CatalogService.get_current_availability`, который вызывает `EktClient`;
4. возвращает найденные позиции в `attachment_items` ответа чата.

Локальные кэшированные цена и остаток никогда не объявляются актуальными. При временной ошибке ekt.kz поле `current` остаётся `false`; подтверждённых данных в ответе нет.

Содержимое вложений, извлечённые строки и сообщения с вложениями не передаются внешней модели. `ChatService` использует локальный parser и каталог; добавление товара остаётся отдельным действием клиента. Это позволяет загружать документы без отправки их текста провайдеру ИИ. Произвольное понимание неструктурированных спецификаций моделью пока не включено. Лучше использовать таблицу «Артикул / Количество» или строки `Артикул: ... Количество: ...`.

UI принимает до пяти PDF/DOCX/XLSX/JPEG/PNG по 10 МБ. OCR изображений выполняется Tesseract в Docker. Количество на отдельной строке, дробное количество или ошибка OCR в артикуле требуют уточнения; сервер не исправляет такие значения догадкой.

Если OCR завершился ошибкой, количество невозможно определить, товар неизвестен или совпадений несколько, это возвращается в `warnings` позиции и в понятном тексте ответа. Пользователь должен уточнить такие позиции.

## Корзина

Распознанная позиция сама по себе не создаёт запись в корзине. Сервер создаёт `PendingOffer` только в существующем безопасном сценарии. Пользователь затем подтверждает конкретный `offer_id`; перед записью выполняется повторная проверка ekt.kz и применяется idempotency key. Подробности: [offer-confirmation-flow.md](offer-confirmation-flow.md).

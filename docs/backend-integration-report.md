# Отчёт: web + FastAPI

Источник бэкенда: ветка `dev2`, коммит `711e323`. `develop2` на origin отсутствует. Бэкенд импортирован без перезаписи существующих незакоммиченных файлов консультанта. Публикация в GitHub не выполнялась.

## Работает и проверено

- FastAPI с PostgreSQL 16: применены все семь миграций, синхронизированы четыре товара синтетического каталога.
- Каталог витрины получает данные из сервера; поиск по SKU, фильтр категории/наличия и карточки связаны с теми же товарами, что чат. Новая начальная выдача — `GET /api/catalog/products`.
- Чат создаёт серверную сессию, отправляет `content` и `attachment_ids`, отображает ответ/карточки и восстанавливает текст истории после перезагрузки вкладки.
- Проверка наличия `DEMO-CABLE-VVG-3X2-5` показала Алматы: 120, Астана: 45; карточка — 165. Это синтетические данные, не остатки EKT.
- XLSX с колонками «Артикул» и «Количество» загружен через UI: сервер извлёк одну позицию, нашёл товар и вернул карточку. Общая фраза о неуспешной автоматической обработке остаётся в ответе, потому что LLM не настроена; извлечение таблицы и поиск при этом работают.
- «Купить» вызывает настоящий endpoint предложения. Бэкенд возвращает 409 из-за неподключённого EKT provider; UI сообщает об отказе, не показывает успешное добавление и не меняет локальную корзину.
- Confirm подключён с `Idempotency-Key`, повторным подтверждением при смене цены и обработкой неуспешных outcomes. Успех реальной корзины не заявляется: он проверяется только на тестовых зависимостях в unit/API-тестах.
- На мобильной ширине 390 px чат занимает экран; горизонтального переполнения не обнаружено.

## Что ещё не работает

| Возможность | Причина |
| --- | --- |
| Реальный каталог, цены и остатки EKT | В dev2 нет реализованного response mapper; `ekt` mode возвращает unavailable. Внешний API в этой задаче не проверялся. |
| Добавление в действующую корзину и checkout EKT | Нет подтверждённого контракта корзины/сессии; providers в offers route — заглушки. |
| Полноценный свободный ИИ-диалог | LLM_API_* и модель не настроены. Используется серверный детерминированный router; CLI-консультант остаётся отдельным. |
| Гарантированный подбор совместимых аналогов | В backend нет отдельного реализованного сценария аналогов; обычный поиск не гарантирует совместимость. |
| Актуальные условия доставки/оплаты | Provider условий пока демонстрационный. |
| OCR при локальном Python-запуске | Системный Tesseract отсутствует; он предусмотрен в Dockerfile. OCR не проверялся на настоящих изображениях. |

## Проверки

- `.venv/bin/python -m pytest -q`: 99 passed. Одно предупреждение Starlette о будущем переходе TestClient с httpx на httpx2.
- `npm test --prefix web`: 2 теста адаптера — unknown/cache значения, контракты сообщений/вложений/предложений, один session ID, отсутствие confirm до отдельного вызова и повтор с тем же ключом.
- `npm run build --prefix web`: TypeScript и production-сборка Vite проходят.
- Реальный браузер + Vite + FastAPI + PostgreSQL: каталог, поиск, ответ об остатках, XLSX, история после reload, отказ предложения, мобильный viewport.

Сборка Docker-образов целиком не была проверена: для сквозной проверки PostgreSQL запущен в Docker, FastAPI и Vite — локально. Инструкция единого Compose-запуска подготовлена; доступность сборочных образов и установка Tesseract зависят от окружения.

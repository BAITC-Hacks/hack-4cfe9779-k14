# Витрина EKT + FastAPI

Ветка `main` содержит демонстрационную копию интерфейса EKT, подключённую к FastAPI из `origin/dev2` (`ee916bc`) и общему ИИ-модулю на `gpt-6-luna`. При настроенном доступе EKT карточки, изображения, цены и остатки получаются из реального API. Это отдельная витрина, а не внедрение на действующий ekt.kz; реальная корзина EKT не подключена.

## Запуск всего приложения

Из корня репозитория:

```bash
cp -n .env.example .env  # Не перезаписывайте уже заполненный файл.
# Задайте POSTGRES_PASSWORD и OPENAI_API_KEY.
# Для EKT: EKT_API_USERNAME, EKT_API_PASSWORD.
docker compose up -d --build
```

Витрина: <http://127.0.0.1:8080>. Swagger: <http://127.0.0.1:8000/docs>. Контейнер API применяет восемь миграций и загружает первые `CATALOG_SYNC_PAGES` страниц каталога (по умолчанию пять). Nginx проксирует `/api` и `/health` к FastAPI. Порты привязаны к localhost; это локальное окружение разработки.

Для живого каталога и ИИ заполните действующие учётные данные EKT и `OPENAI_API_KEY`. Пустые EKT-поля пропускают начальную загрузку каталога: API запускается, каталог сообщает о недоступности, синтетические товары не подставляются. Без настроенной модели свободный диалог недоступен; вместо OpenAI можно отдельно настроить совместимый провайдер через `LLM_API_*` и `LLM_MODEL`.

## Разработка без пересборки контейнеров

Нужны Python 3.12, `uv`, Node 22.18+ (рекомендуется 24) и Docker для PostgreSQL. Из корня проекта:

```bash
cp .env.example .env  # Только если файла ещё нет.
# Установите одинаковый пароль в POSTGRES_PASSWORD и DATABASE_URL.
docker compose up -d db
uv venv .venv  # Только если окружения ещё нет.
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/alembic upgrade head
PYTHONPATH=src .venv/bin/python -m app.catalog_sync
PYTHONPATH=src .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
cd web
npm ci
npm run dev
```

Откройте адрес Vite. `/api` автоматически проксируется на `127.0.0.1:8000`; настройки браузера и CORS не требуются. `uv sync` управляет отдельным CLI-консультантом и может удалить зависимости FastAPI из общего `.venv`: после него повторите установку `requirements.txt`.

По умолчанию `VITE_ASSISTANT_API_BASE=/api`. Для прямого подключения укажите полный префикс, например `http://127.0.0.1:8000/api`, и задайте `WIDGET_ORIGIN` на сервере равным точному origin витрины. Секреты никогда не помещайте в `VITE_*`.

Прежний автономный режим доступен явно через `VITE_ASSISTANT_API_BASE=demo` в `web/.env.local`. В нём старые карточки и локальная корзина остаются демонстрационными. При недоступности API серверный режим не переключается на них автоматически.

## Подключённые эндпоинты

| Интерфейс | API |
| --- | --- |
| Страницы каталога без запроса | `GET /api/catalog/source-page?page=N` |
| Режим каталога, ИИ и корзины | `GET /api/catalog/status` |
| Поиск | `GET /api/catalog/search?q=...&limit=100` |
| Цена, остаток, характеристики карточек | `GET /api/catalog/products/{article}/fresh` |
| Создание сессии | `POST /api/chat/sessions` |
| История | `GET /api/chat/sessions/{id}/messages` |
| Сообщение | `POST /api/chat/sessions/{id}/messages`, JSON `{content, attachment_ids}` |
| Вложение | `POST /api/chat/sessions/{id}/attachments`, multipart `file` |
| Предложение из кнопки «Купить» | `POST /api/chat/sessions/{id}/offers`, JSON `{product_identifier, article, quantity}` |
| Подтверждение кнопкой | `POST /api/chat/sessions/{id}/offers/{offer_id}/confirm`, `Idempotency-Key` |

Сессия сохраняется в `sessionStorage` вкладки; история загружается с сервера. После пересоздания базы отсутствующая сессия заменяется новой. При обновлении страницы восстанавливается текст истории; карточки и незавершённые предложения заново не восстанавливаются, так как API истории их не возвращает.

Цена и остаток показываются только после успешного `/fresh`. Если сведения отсутствуют или источник недоступен, UI пишет «Цена не предоставлена»/«Наличие не подтверждено». Ноль и неизвестное значение различаются. Единица товара не выдумывается, если источник её не передал. Страницы каталога загружаются из EKT по 20 товаров. Поиск ограничен индексированной частью каталога и выдаёт до 100 результатов; просмотренные страницы расширяют индекс. Это не полный поиск по всему ассортименту партнёра.

Файлы: до пяти PDF, DOCX, XLSX, JPEG/PNG по 10 МБ за отправку. Старые DOC/XLS не поддерживаются бэкендом. Извлечение текста/таблиц и сопоставление артикулов выполняются локально, содержимое вложений внешней модели не передаётся. Количество должно быть целым и однозначным; OCR может требовать уточнения. PDF распознаются по текстовому слою: OCR сканированных PDF не реализован, для OCR загрузите страницу как JPEG/PNG. Tesseract для OCR установлен в Docker-образе; при запуске Python напрямую его нужно установить отдельно.

Предложение создаётся отдельно от записи в корзину. Текст «да» не подтверждает серверное предложение. Только кнопка «Да, добавить» вызывает confirm; повтор запроса использует тот же ключ. При смене цены показывается новое предложение с новым подтверждением. Действующий backend получает свежие EKT-данные и создаёт предложение. При подтверждении `UnavailableCartGateway` возвращает `cart_unavailable`; UI не показывает успешное добавление. Runtime mock-корзина удалена в новой dev2. Предложение из ответа чата отображается напрямую, без дублирующего POST /offers.

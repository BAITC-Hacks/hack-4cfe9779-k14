# Каталог товаров и API ekt.kz

## Назначение

Документ описывает два независимых слоя:

1. `app/integrations/ekt_api.py` — HTTP-клиент партнёрского API на `httpx` с Basic Auth. Он скрывает URL/пагинацию/формат ошибок внешнего сервиса и нормализует товары в `EktProduct`.
2. `app/catalog.py` — PostgreSQL-репозиторий локального поискового каталога. Он хранит основные поля в типизированных колонках, а разнородные характеристики — в `jsonb`.

API чата и его временные предложения/загрузки/идемпотентность остаются без БД. Наличие PostgreSQL в проекте относится только к каталогу товаров.

## Внешний API

Настройки сервера:

- `EKT_API_BASE_URL` — базовый URL API; значение по умолчанию `https://ekt.kz/api/`.
- `EKT_API_USERNAME` и `EKT_API_PASSWORD` — учётные данные Basic Auth.

Секреты нельзя отдавать браузеру, коммитить или записывать в логи. Не включайте автоматическое следование редиректам: это помогает не переслать Basic Auth на другой хост.

Методы клиента:

- `list_products(page=1)` → `list[EktProduct]`, запрос `GET /products?page=1`.
- `get_product(product_id)` → `EktProduct`, запрос `GET /products/detail?id=...`.

Документы проекта подтверждают пути, параметр `page` и `id`, но не точную JSON-схему, доступные поля, лимиты и rate limits. Поэтому `_extract_rows` и `_normalize_product` поддерживают несколько распространённых обёрток/алиасов и должны быть проверены против реального ответа до использования в production. Отсутствующие `price`, `warehouse_stocks` и сертификаты остаются неизвестными; адаптер не должен придумывать значения.

Сетевые/HTTP ошибки преобразуются в `EktApiUnavailable`; неподдерживаемый ответ или обязательные поля — в `EktApiContractError`. Текст ошибок не содержит логин, пароль или тело ответа.

## Схема PostgreSQL

Таблица `products` создаётся через `ProductCatalog.initialize()` для локального старта. Для production используйте версионируемые миграции. Состав:

| Колонка | Тип | Назначение |
| --- | --- | --- |
| `id` | `TEXT PRIMARY KEY` | Идентификатор товара у партнёра |
| `article` | `TEXT` | Артикул для точного поиска |
| `name` | `TEXT NOT NULL` | Наименование |
| `category` | `TEXT` | Категория |
| `attributes` | `JSONB` | Разнородные технические характеристики |
| `certificate_links` | `JSONB` | Ссылки на сертификаты, если предоставлены |
| `price` | `NUMERIC(14,2)` | Цена, если поле есть в источнике |
| `warehouse_stocks` | `JSONB` | Остатки по складам, если поле есть в источнике |
| `product_url` | `TEXT` | Ссылка на сайте |
| `updated_at` | `TIMESTAMPTZ` | Время обновления из источника |
| `search_document` | generated `TSVECTOR` | Полнотекстовый документ из артикула, названия, категории и характеристик |

Индексы: GIN по `search_document`, B-tree по артикулу и категории, GIN `jsonb_path_ops` по характеристикам. Поиск использует конфигурацию PostgreSQL `simple`, чтобы не привязываться к словарю одного языка; релевантность полнотекстовой части сортируется через `ts_rank`. Точное совпадение артикула при желании интегратор может добавить отдельным приоритетом.

`ProductCatalog.search(query, category=None, attributes=None, limit=20)` ищет полнотекстовый запрос и применяет точное совпадение категории и JSONB containment фильтр (например `{"voltage": "220V"}`). Лимит ограничен диапазоном 1–100.

## Синхронизация

Синхронизатор должен последовательно обходить страницы `list_products(page=n)`, преобразовывать товары и пакетно вызывать `upsert_products`. Для выбранного товара можно запросить актуальную карточку через `get_product`, затем обновить строку через `upsert_product`.

Частоту обновления, инкрементальный курсор, поведение при удалении товара и правила ретраев необходимо согласовать с партнёром: эти детали не заданы. Поиск по каталогу подходит для нахождения кандидатов, но цена/остаток перед пользовательским утверждением и изменением корзины должны перепроверяться через актуальный доверенный источник.

## Пример использования

```python
from app.catalog import ProductCatalog
from app.integrations.ekt_api import EktApiClient

catalog = await ProductCatalog.connect(database_url)
try:
    async with EktApiClient() as partner:
        page = await partner.list_products(page=1)
        await catalog.upsert_products(page)

    matches = await catalog.search(
        "кабель медный",
        category="cables",
        attributes={"cores": 3},
    )
finally:
    await catalog.close()
```

Не вызывайте `initialize()` на каждый пользовательский запрос. Запускайте схему при старте/миграции отдельно от поиска.
